# Reviewer 2 – Comment 2: Controlled congestion-representation experiment

This package is designed to answer Reviewer 2's core request **without changing the planner**. The experimental question is not “which complete algorithm is best?” It is:

1. Does **exact committed spatiotemporal reservation information** provide a better congestion representation than indirect historical or learned/predicted information?
2. Given the **same exact reservation information**, is the proposed **Gaussian smoothing** preferable to raw occupancy and plausible alternative kernels/decay functions?

## 1. Strict control principle

For every formal comparison, the following are identical:

- the same direct one-shot task instance;
- the same task order and initial priorities;
- the same original one-shot CPS-A `TicketManager` hard node and reverse-edge reservation constraints;
- the same `ControlledSegmentPlanner` search code and neighbor expansion;
- the same movement coefficient `alpha=1.0`;
- the same **fixed implementation turn penalty = 0.5** (there is no beta parameter in the original code);
- the same current-congestion coefficient `gamma=5.0`;
- the same map-specific heuristic setting: Map A uses Manhattan + congestion look-ahead; Maps B/C use Manhattan only;
- the same `omega=50.0` wherever congestion look-ahead is enabled;
- the same waiting rule, update interval, timeout and rollback mode.

The program writes a `common_planner_signature` for every run and refuses paired export if this signature differs between representations.

Planning starts from an **empty reservation table**. There is no pre-planned schedule and no inserted-task protocol.

Formal loads are fixed to the R1-aligned settings:

- Map A: 50, 70 tasks
- Map B: 250, 280 tasks
- Map C: 150, 200 tasks

## 2. Two orthogonal controlled comparison families

### A. Information-source experiment: why exact reservations?

The smoothing kernel is fixed to the **same CPS-A 3D Gaussian** in all three methods. Only the source of the raw occupancy estimate changes.

| Representation | Raw congestion information | Soft kernel used by planner |
|---|---|---|
| `gaussian` | current exact committed reservations | CPS-A Gaussian |
| `historical_gaussian` | mean raw occupancy from disjoint past calibration episodes | **same CPS-A Gaussian** |
| `learned_gaussian` | conditional learned prediction of raw occupancy for the current task set | **same CPS-A Gaussian** |

Therefore, `gaussian` vs `historical_gaussian` vs `learned_gaussian` isolates the **information source**. It does not confound the comparison with a different planner or a different smoothing kernel.

### B. Kernel experiment: why Gaussian?

The source is fixed to the **same current exact committed reservations** in every method. Only the transformation from raw reservations to the soft congestion field changes.

| Representation | Information source | Transformation |
|---|---|---|
| `raw` | exact committed reservations | no smoothing |
| `gaussian` | exact committed reservations | proposed Gaussian kernel |
| `exponential` | exact committed reservations | exponential decay |
| `linear` | exact committed reservations | compact linear decay |
| `uniform` | exact committed reservations | uniform/box kernel |

`exponential` and `linear` use the same finite support as Gaussian and are calibrated to match the Gaussian discrete spatial and temporal second moments. `uniform` uses the same support and unit-mass normalization but is intentionally not second-moment matched.

`no_field` is retained as a collision-only control, not as part of the kernel/source isolation argument.

## 3. Historical representation

Historical information is generated **offline** from independent calibration seeds (formal default: 10000–10029; overlap with the actually selected formal test seeds is rejected at runtime).

Each calibration episode:

1. uses the same map and task generator;
2. uses the same task load as the target condition;
3. is planned by the same controlled CPS-A search core with **soft congestion disabled** (`no_field`) and rollback off;
4. records the resulting raw occupancy `psi(x,y,t)`;
5. contributes to `E[psi(x,y,t)]` across calibration episodes.

Using collision-only calibration prevents the historical baseline from being generated by the proposed Gaussian method itself. At test time this historical raw occupancy is convolved with the **same Gaussian kernel** used by exact CPS-A.

## 4. Learned/predicted representation

The learned baseline is a **conditional spatiotemporal occupancy predictor**, not a second path planner. It receives only congestion-representation inputs:

- current task start-count map;
- pickup-count map;
- destination-count map;
- spatial coordinates;
- normalized time;
- obstacle mask.

Its supervision is the raw occupancy generated by the **same disjoint collision-only calibration episodes** used above. Calibration and validation are split by complete episode, not by individual time slice, to avoid leakage.

The network uses a small FNO-style convolution architecture adapted from the predictive modeling idea already present in `experiment.zip/MCCP`, but it is retrained on the actual Map A/B/C geometries and current task distributions. It predicts **raw occupancy probability**, not a pre-smoothed field. At test time its prediction is convolved with the **same CPS-A Gaussian kernel**. This is deliberate: the source-family comparison must differ only in information source.

The formal test task instances are never used in training. Metadata stored with each model records calibration seeds and the code rejects any artifact that reports overlap with formal test seeds.

## 5. Primary and confirmation settings

The **primary Reviewer-2 representation experiment uses rollback OFF**. This removes priority-repair interactions and makes the representation itself easier to isolate.

A separate confirmation run may use rollback ON for every representation under the exact same setting:

```bash
python run.py --suite both
```

Do not combine rollback-on and rollback-off rows into one estimate.


The tests cover, among other things:

## 9. Prepare formal historical/learned references

This is a one-time offline preparation step:

```bash
python prepare_reference_artifacts.py \
  --output reference_artifacts \
  --calibration-seeds 30 \
  --calibration-seed-start 10000 \
  --epochs 40 \
  --samples-per-episode 10
```

This is an **offline one-time preparation step**, not part of the five formal test repetitions.
With the default three maps and two loads per map it produces six historical fields
(`A_50`, `A_70`, `B_250`, `B_280`, `C_150`, `C_200`) and only three learned models
(one model for each map, trained from that map's two calibration loads). Formal experiments
load and reuse these artifacts; they do not regenerate historical data or retrain the network.
If the same complete preparation command is accidentally run again against the same output
directory, the script now detects the identical manifest and reuses the existing artifacts.
Use `--force` only when intentional regeneration is required.

The preparation manifest, per-condition historical metadata, calibration cache metadata and learned-model metadata are written to the reference directory.

## 11. Formal output interpretation

`raw_results.csv` contains fields that make the isolation explicit:

- `soft_information_source`
- `soft_kernel`
- `representation_family`
- `common_planner_signature`
- `task_hash`
- `initial_order_hash`

For the paper/response letter, the most important contrasts are:

### Exact-information claim

- `gaussian - historical_gaussian`
- `gaussian - learned_gaussian`

These keep Gaussian fixed and test whether exact committed reservations outperform indirect information.

### Gaussian-kernel claim

- `gaussian - raw`
- `gaussian - exponential`
- `gaussian - linear`
- `gaussian - uniform`

These keep exact committed reservations fixed and test whether Gaussian smoothing is preferable to plausible alternatives.

`pairwise_statistics.csv` labels these as separate `comparison_question` families.

## 12. Important interpretation rule

Do **not** claim in advance that exact reservation information or Gaussian smoothing is superior. The revised experiment is designed to test those hypotheses. The manuscript/response should report the observed effect sizes, confidence intervals and statistical tests, including negative or topology-dependent findings.

This is especially important because Reviewer 2's concern is scientific isolation, not simply adding another baseline.
