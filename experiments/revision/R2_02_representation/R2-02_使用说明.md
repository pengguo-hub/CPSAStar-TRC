# R2-02 Controlled Congestion Representation Experiment 使用说明

## 1. 这个实验在做什么

本实验用于回应 Reviewer 2 第 2 条意见：在 **其他规划条件完全一致** 的情况下，直接比较不同 congestion representations，从而分别回答两个问题：

1. **为什么要使用精确的 committed reservation 信息？**  
   固定同一个 Gaussian 核，只改变 congestion 信息来源：
   - `gaussian`：当前已经 committed 的精确 reservation occupancy；
   - `historical_gaussian`：独立历史运行得到的平均 occupancy；
   - `learned_gaussian`：由当前任务需求预测得到的 occupancy。

2. **为什么使用 Gaussian smoothing？**  
   固定同一个 exact committed reservation 信息源，只改变 soft congestion 的表征核：
   - `raw`
   - `gaussian`
   - `exponential`
   - `linear`
   - `uniform`

此外还保留：

- `no_field`：只有 hard reservation collision constraints，不使用 soft congestion field。

正式实验中，所有方法共享相同的任务、任务顺序、hard reservation constraints、CPS-A 搜索逻辑、固定转弯惩罚 0.5、`gamma=5.0`、等待规则、update interval 和其他规划参数。**允许变化的只有 soft congestion representation。**

# 2. 最重要的使用逻辑

整个实验分为两个阶段：

## 阶段 A：只做一次 reference preparation

运行：

```text
prepare_reference_artifacts.py
```

它负责：

- 生成 historical congestion reference；
- 生成 learned predictor 的训练数据；
- 训练 Map A / B / C 对应的 learned predictor；
- 保存到 `reference_artifacts/`。

**这一阶段只需要完整运行一次。**

它不是“正式实验重复 30 次”。默认的 30 个 calibration seeds 是给 historical / learned baseline 准备离线参考数据用的。

---

## 阶段 B：正式跑 5 次 controlled comparison

运行：

```text
run_representation_experiment.py
```

它负责：

- 读取已经准备好的 `reference_artifacts/`；
- 正式生成 5 个独立 test seeds；
- 对同一个 test instance 分别运行所有 congestion representations；
- 自动保存原始结果；
- 自动做统计分析；
- 自动生成图。

**正式实验默认只有 5 次独立重复。**

默认正式 test seeds 是：

```text
42, 43, 44, 45, 46
```

historical / learned calibration seeds 默认是：

```text
10000 ~ 10029
```

两组 seed 完全独立，避免数据泄漏。

## 5.2 这些参数分别是什么意思

### `--output reference_artifacts`

reference 输出目录。

默认值本来就是：

```text
reference_artifacts
```

里面会包含类似：

```text
historical_A_50.npz
historical_A_70.npz
historical_B_250.npz
historical_B_280.npz
historical_C_150.npz
historical_C_200.npz

learned_A.pt
learned_B.pt
learned_C.pt

preparation_manifest.json
calibration_cache/
...
```

其中：

- Historical：按 `map × load` 保存；
- Learned predictor：每张地图一个网络，而不是每个负载重新训练一个网络。

因此：

```text
Map A 的 50 / 70 calibration 数据 -> 共同训练 learned_A.pt
Map B 的 250 / 280 calibration 数据 -> 共同训练 learned_B.pt
Map C 的 150 / 200 calibration 数据 -> 共同训练 learned_C.pt
```

---

### `--calibration-seeds 30`

用于构建 historical statistics 和 learned training data 的独立 calibration episodes 数量。

默认：

```text
30
```

**注意：这不是正式实验运行 30 次。**

正式结果仍然是 5 次。

不建议把这里也改成 5，因为 historical / learned baseline 需要足够的离线数据，太少会使这两个 baseline 本身不稳定。

---

### `--calibration-seed-start 10000`

第一条 calibration seed。

默认 30 个 seed 因此是：

```text
10000 ~ 10029
```

它们必须与正式 test seeds 不重叠。

正式程序会自动检查这一点。

---

### `--epochs 40`

Learned occupancy predictor 的训练 epoch 数。

默认：

```text
40
```

---

### `--samples-per-episode 10`

每个 calibration episode 选择多少个时间片作为神经网络训练样本。

默认：

```text
10
```

---

### `--batch-size 32`

神经网络训练 batch size。

默认：

```text
32
```

通常不需要改。

---

### `--hidden 24`

Learned predictor 的 hidden channel 数量。

默认：

```text
24
```

正式受控实验建议保持不变。

---

### `--timeout`

单个 calibration planner 的规划时间上限。

如果不传，使用 `config.py` 中：

```python
timeout = 60.0
```

---

### `--maps A B C`

只准备指定地图。

例如：

```bash
python prepare_reference_artifacts.py --maps A B
```

正式完整实验不要加这个参数，默认会自动准备 A、B、C 三张地图。

---

### `--smoke`

只做极小规模测试。

不能作为正式 reference。

---

### `--force`

强制重新生成 reference artifacts。

例如：

```bash
python prepare_reference_artifacts.py --force
```

**正常情况下不要使用。**

如果完全相同的 `reference_artifacts` 已经生成完成，再次运行准备脚本时程序会直接显示：

```text
Reference artifacts already complete; reusing without regenerating/training
```

因此：

> 同一个地图、同一个负载不会因为你重新运行正式实验而反复生成历史数据，也不会反复训练网络。

# 7. 正式实验参数说明

## `--seeds 5`

正式独立重复次数。

这里才是论文中的：

```text
5 independent runs
```

默认正式值本身就是：

```text
5
```

---

## `--seed-start 42`

正式实验起始 seed。

配合 `--seeds 5`：

```text
42, 43, 44, 45, 46
```

同一个 seed 下，不同 representations 使用相同任务，因此是 matched / paired comparison。

---

## `--seed-list`

如果你的其他实验已经固定使用某 5 个 seed，可以直接指定：

```bash
python run_representation_experiment.py --seed-list 10 20 30 40 50 --references reference_artifacts --output results_formal
```

使用 `--seed-list` 时，不要再同时使用：

```text
--seeds
--seed-start
```

否则程序会报错。

---

## `--suite primary`

控制 rollback 模式。

### `primary`

```text
rollback OFF
```

这是 Reviewer 2 第 2 条的主实验，推荐正式使用。

原因是这里要尽量隔离 congestion representation，不希望 priority repair / rollback 干扰判断。

### `confirmation`

```text
rollback ON
```

作为额外确认实验。

### `both`

同时运行：

```text
rollback OFF + rollback ON
```

运行量会加倍。

Reviewer 2 第 2 条的主结果建议首先使用：

```text
--suite primary
```

---

## `--references reference_artifacts`

指定前一步已经生成好的 historical / learned reference。

正式程序只会读取这些文件：

- 不会重新生成 historical 数据；
- 不会重新训练 learned predictor。

Learned 方法对每个正式 test instance 会做 inference，这是正常的；但是使用的是**同一个已经训练好的网络**。

---

## `--output results_formal`

正式结果输出目录。

建议使用：

```text
results_formal
```

如果不传，脚本默认使用：

```text
results
```

---

## `--maps A B C`

只运行指定地图。

正式完整实验不要传这个参数，默认就是 A、B、C 全部地图。

---

## `--loads`

临时覆盖所有选中地图的任务数。

例如：

```bash

```

正式实验一般**不要使用 `--loads`**。

默认正式负载已经在 `config.py` 固定为：

```text

Map B = 250, 280
Map C = 150, 200
```

---

## `--representations`

指定要跑哪些 congestion representations。

正式默认已经包括：

```text

raw
gaussian
exponential
linear
uniform
historical_gaussian
learned_gaussian
```

正式完整实验不要删。

如果只是临时调试，例如：

```bash
python run_representation_experiment.py --representations gaussian raw --maps A --loads 50 --seeds 1 --references reference_artifacts --output debug_test
```

但这种结果不能代替正式实验。

---

## `--timeout`

覆盖单次 planner timeout。

例如：

```bash
--timeout 120
```

如果不指定，默认：

```text
60 s
```

为了公平，所有 representations 使用相同 timeout。

---

指定 shared task instance cache。

通常不需要手动指定。

脚本会自动保存和复用同一个 seed 对应的任务实例，以确保不同 representation 使用完全相同任务。

## `--no-plots`

不生成图，只跑结果和统计。

---

## `--no-analysis`

不做统计分析。

注意：如果没有同时使用 `--no-plots`，plotting 仍会触发统计分析。

正式运行不要使用这两个参数。

只打印正式实验计划，不真正运行。

强烈建议正式实验前先执行一次：

```bash
python run_representation_experiment.py --seeds 5 --seed-start 42 --suite primary --references reference_artifacts --output results_formal --dry-run
```


# 13. Historical / Learned 会不会在正式 5 次中重新生成？

不会。

## Historical

例如：

```text
historical_A_50.npz
```

只在 reference preparation 阶段生成一次。

正式：

```text
seed 42
seed 43
seed 44
seed 45
seed 46
```

全部读取同一份 historical reference。

---

## Learned predictor

例如：

```text
learned_A.pt
```

只训练一次。

正式 5 个 seed 都加载同一个：

```text
learned_A.pt
```

但每个正式 test instance 的任务分布不同，所以网络会针对当前任务做一次 inference。

也就是：

```text
训练：只做一次
预测：每个正式实例做一次
```

这是正常且必要的。

---

# 14. 为什么 Historical 是 map × load，而 Learned 是每张地图一个模型？

Historical 表示的是：

```text
某张地图 + 某个运输负载
```

下过去运行形成的平均 spatiotemporal occupancy。

因此：

```text
A-50 与 A-70 的历史交通强度本身不同
```

需要分别保存。

Learned predictor 则学习的是：

```text
当前任务需求 -> future raw occupancy
```

所以 Map A 的一个网络可以接收不同当前任务需求，从而分别预测 A=50 和 A=70 的 congestion distribution。

---

## Calibration seeds

```text
10000 ~ 10029
```

用途：

- Historical reference；
- Learned training data。

不计入论文的 5 次正式重复。

## Formal test seeds

```text
42 ~ 46
```

用途：

- 最终比较；
- 统计表；
- 图；
- Reviewer response。

这两组不能重叠。

程序会自动检查。

# 16. 修改参数以后，旧结果能不能继续用？

原则：**protocol 改了，就不要把新旧结果放到同一个输出目录。**

例如你修改了：

- seed；
- map load；
- representation；
- gamma；
- omega；
- Gaussian 参数；
- rollback mode；
- 源代码。
